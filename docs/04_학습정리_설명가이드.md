## 1. HTML / CSS / JavaScript가 각각 하는 일

**① 한 줄 답**
HTML은 화면에 *무엇이 있는지*(구조), CSS는 *어떻게 보이는지*(모양), JavaScript는
*사용자가 누르면 무슨 일이 일어나는지*(동작)를 담당한다.

**② 내 프로젝트에서는**

| 역할 | 내 파일 | 구체적으로 하는 일 |
|---|---|---|
| HTML (구조) | `index.html`, `book-info.html`, `discussion.html`, `guide.html` | 4개 페이지의 제목, 입력창(`#title-input`), 선택 상자(`#age-select`, `#purpose-select`), 버튼, 결과 칸(`#result`)을 만든다. 결과 칸은 처음엔 `hidden`이다 |
| CSS (모양) | `css/style.css` | 색·간격을 `:root` 변수로 관리, 메뉴 배치(flex), 카드 디자인. **반응형**: `@media (min-width: 640px)`에서 결과를 2단으로, `900px`에서 여백을 넓힌다. 모바일에서는 1단 |
| JS (동작) | `js/common.js`, `js/book-info.js`, `js/discussion.js` | 폼 제출을 감지 → 입력 검사 → 서버에 요청 → 결과를 화면에 채움. 현재 페이지 메뉴에 밑줄(`setActiveNav`) |

- 세 파일을 **역할별로 나눈 이유**: 디자인을 바꿀 땐 CSS만, 동작을 바꿀 땐 JS만
  고치면 되고, 오류가 났을 때 어디를 볼지 좁혀진다.
- 반응형이 되는 이유: 각 HTML `<head>`의 `<meta name="viewport" ...>`와 CSS 미디어쿼리.
  (375px 모바일 / 1280px 데스크톱에서 직접 확인함. 모바일에서 가로 스크롤 없음)

**③ 말로 설명하기 (30초)**
> "HTML로 입력창과 버튼, 결과가 나올 빈 칸을 만들었고, CSS로 카드 모양과 색을 입히고
> 화면 폭이 640px, 900px을 넘으면 배치가 바뀌도록 반응형을 적용했습니다. JavaScript는
> 버튼을 눌렀을 때 입력값을 검사하고 서버에 요청을 보낸 뒤, 돌아온 결과를 결과 칸에 채워
> 보여주는 역할입니다. 셋이 각자 역할이 달라서 수정할 때 어디를 고칠지 바로 알 수 있습니다."

**④ 예상 질문**
- *결과 칸을 왜 처음에 `hidden`으로 두나요?* → 결과가 있을 때만 보여주려고. JS가
  `resultEl.hidden = false`로 켠다.
- *JS 없이 HTML/CSS만으로 이 서비스가 되나요?* → 화면은 나오지만, 서버 호출과 결과 표시는
  JS가 없으면 불가능하다.

## 2. 입력 → fetch 요청 → 응답 → 화면 반영 흐름

**① 한 줄 답**
사용자가 버튼을 누르면 JS가 입력값을 검사해 `fetch`로 서버에 JSON을 보내고, 서버가 돌려준
JSON을 JS가 꺼내서 HTML 요소의 글자로 넣는다.

**② 내 프로젝트에서는 — "도서 정보 조회" 한 번의 여정** (`js/book-info.js`, `js/common.js`)

1. 사용자가 `책 제목`에 "데미안"을 넣고 **조회하기**를 누른다 → 폼의 `submit` 이벤트 발생
2. `event.preventDefault()` — 페이지가 새로고침되는 기본 동작을 막는다
3. **입력 검사**: 제목이 비었으면 "책 제목을 입력해주세요." 표시 후 **서버에 보내지 않고 끝**
4. 버튼을 `disabled`로 바꾸고 "조회 중..." 표시 (중복 클릭 방지)
5. `fetchJSON('/api/book-info', { method: 'POST', body: JSON.stringify({ title }) })`
   — `common.js`의 함수. **15초 타임아웃**(`AbortController`)과 오류 메시지 통일을 담당
6. 서버가 `{ "title", "author_intro", "summary" }` JSON으로 응답
7. JS가 `authorIntroEl.textContent = data.author_intro` 처럼 **글자로 채우고**
   `resultEl.hidden = false`로 결과 카드를 보여준다
8. `finally`에서 버튼을 원래대로 되돌린다 (성공/실패와 상관없이)

**페이지 간 전달**: 결과 아래 "이 책으로 토론 주제 추천받기" 버튼 →
`discussion.html?title=데미안` 으로 이동 → 토론 페이지의 JS가
`URLSearchParams`로 제목을 읽어 입력창에 미리 채워 준다.

**실패 처리 3종** (과제 요구사항)

| 상황 | 어떻게 처리 | 화면 |
|---|---|---|
| ① 빈 입력 / 필수값 누락 | JS에서 먼저 막음 (서버도 400으로 한 번 더 검사) | "책 제목을 입력해주세요." |
| ② API 오류 (AI/서버 실패) | 서버가 502 + 메시지, JS가 `catch`에서 표시 | "정보를 가져오지 못했어요. 잠시 후 다시 시도해주세요." |
| ③ 지연 / 타임아웃 | 15초 넘으면 `AbortController`로 중단 | "응답이 지연되고 있어요…" |

- 결과를 넣을 때 `innerHTML`이 아니라 **`textContent`** 를 쓴 이유: AI가 준 글자에 HTML
  코드가 섞여 있어도 코드로 실행되지 않고 **글자 그대로** 보여, 안전하다.

**③ 말로 설명하기 (1분)**
> "사용자가 책 제목을 입력하고 버튼을 누르면 submit 이벤트가 발생하고, JS가 먼저 빈 값인지
> 검사합니다. 통과하면 fetch로 `/api/book-info`에 제목을 JSON으로 POST합니다. 그동안 버튼은
> 잠가서 중복 요청을 막고, 15초가 넘으면 타임아웃 메시지를 보여줍니다. 서버가 저자 소개와
> 줄거리를 JSON으로 돌려주면 JS가 그 값을 화면의 요소에 textContent로 넣고 숨겨둔 결과
> 카드를 보여줍니다. 실패하면 catch에서 원인별 메시지를 화면에 표시합니다."

**④ 예상 질문**
- *`async/await`는 왜 쓰나요?* → 서버 응답을 기다리는 동안 화면이 멈추지 않게, 응답이 오면
  이어서 실행하려고.
- *왜 GET이 아니라 POST인가요?* → 제목·연령대 같은 입력을 요청 본문(JSON)에 담아 보내려고.
- *`preventDefault`를 빼면?* → 폼 제출로 페이지가 새로고침되어 결과가 사라진다.

## 3. Vercel Serverless Functions와 프론트 → 백엔드(Python) 호출 구조

**① 한 줄 답**
Serverless Function은 **서버를 직접 켜 두지 않고, 요청이 올 때만 Vercel이 코드를 실행해
주는 방식**이다. 프론트는 같은 주소의 `/api/...`로 요청하고, 그 요청을 Python 코드가 받는다.

**② 내 프로젝트에서는**

- **백엔드 = `api/app.py` 하나** (Flask 앱). 엔드포인트 2개:
  - `POST /api/book-info` — 저자 소개 + 줄거리
  - `POST /api/discussion-topics` — 이야깃거리 + 토론 주제
- Vercel에게 "이 파일이 시작점"이라고 알려주는 설정: `pyproject.toml`의
  `[tool.vercel] entrypoint = "api.app:app"`
- 프론트는 `fetch('/api/book-info')`처럼 **상대 경로**로 부른다 → 같은 사이트(같은 주소)라서
  별도의 서버 주소·CORS 설정이 필요 없다.
- 서버가 하는 일: ① 받은 값 검사(빈 값이면 400) ② 환경변수에서 API 키를 꺼냄 ③ Gemini에
  질문(프롬프트) 전달 ④ 받은 답을 JSON으로 정리해 응답
- **왜 프론트에서 AI를 직접 부르지 않나?** 프론트(JS)는 사용자 브라우저에서 실행되어 코드가
  전부 공개된다. AI 호출을 프론트에서 하면 API 키가 노출된다. → **서버(Function)를 중간에
  두고 키는 서버만 갖는다.**
- 현재 구조에서는 **화면 파일(HTML/CSS/JS)도 같은 Flask 앱이 내준다**(`/`, `/<page>.html`,
  `/css|js|images/...` 라우트, 허용된 파일만). 배포 로그에서도 `/` 요청이 Function으로 처리되는 걸 확인했다.
- Serverless의 특징: 서버 관리 불필요, 요청 있을 때만 실행(사용량만큼 과금),
  첫 요청은 조금 느릴 수 있음(콜드 스타트).
- 처음엔 `api/book-info.py`, `api/discussion-topics.py` **파일 2개**(파일별 자동 라우팅)로
  만들었으나, 최신 Vercel Python 런타임이 인식하지 못해 **Flask 앱 1개로 합쳤다**
  (아래 5번의 "겪은 문제" 참고).

**③ 말로 설명하기 (1분)**
> "프론트는 정적인 HTML/CSS/JS이고, AI를 부르는 부분은 Vercel Serverless Function으로 만든
> Python(Flask) 코드입니다. 서버를 따로 운영하지 않고 요청이 올 때만 Vercel이 `api/app.py`를
> 실행해 줍니다. 브라우저 JS는 같은 주소의 `/api/book-info`로 요청만 보내고, 서버 함수가
> 환경변수의 API 키로 Gemini를 호출한 다음 결과를 JSON으로 돌려줍니다. AI를 서버에서
> 호출하는 이유는 프론트 코드는 공개되기 때문에 키를 숨길 수 없어서입니다."

**④ 예상 질문**
- *Serverless라고 해서 서버가 없는 건가요?* → 서버는 있지만 내가 관리하지 않고, 필요할 때만
  Vercel이 띄워서 실행한다는 뜻.
- *`/api/book-info`는 어디로 가나요?* → Vercel이 `api.app:app`(Flask)으로 넘기고, Flask의
  `@app.route("/api/book-info")` 함수가 처리한다.

## 4. 환경 변수로 API 키를 안전하게 관리해야 하는 이유

**① 한 줄 답**
API 키는 **내 돈·내 계정과 연결된 비밀번호**라서, 코드나 GitHub에 올라가면 남이 훔쳐
쓸 수 있다. 그래서 코드 밖의 **환경 변수**에 두고, 코드는 이름으로만 꺼내 쓴다.

**② 내 프로젝트에서는**

| 어디서 | 어떻게 |
|---|---|
| 코드 (`api/app.py`) | `os.environ.get("GEMINI_API_KEY")` — 키 값이 코드에 **없다**. 이름만 있다 |
| 로컬 | `.env.local` 파일에 `GEMINI_API_KEY=...` 저장. **`.gitignore`에 등록**해서 GitHub에 안 올라감. `python-dotenv`가 실행 시 읽어옴 |
| 팀/새 컴퓨터용 안내 | `.env.local.example` — 키 자리에 안내 문구만 있는 **견본**(이건 올려도 안전) |
| 배포 (Vercel) | `vercel env add GEMINI_API_KEY production`으로 등록. 대시보드에서도 값이 **Hidden** 처리 |
| 브라우저(JS) | 키를 **아예 모른다**. JS는 우리 서버 `/api/...`만 호출 |

- 키가 새면 벌어지는 일: 타인이 내 키로 AI를 마구 호출 → 요금 폭탄 / 사용 한도 소진 / 계정 정지.
  GitHub 공개 저장소에 키가 올라가면 자동 수집 봇이 **몇 분 안에** 찾아내기도 한다.
- **실제로 겪은 일 (2026-09-18)**: 디버깅 중 AI 코딩 도구가 `.env.local`을 `cat`으로 출력해
  키 전체가 화면(대화창)에 노출됐다. → 즉시 키 **폐기·재발급**. 교훈: 키 파일은 전체 출력하지
  말고 길이·앞글자만 확인한다. (이후 작업에서도 그렇게 함)
- 환경 변수 이름은 **대소문자를 구분**한다: `gemini_API_KEY`로 저장했더니 코드가 못 읽어서
  "키 없음"이 됐고, `GEMINI_API_KEY`로 고쳐서 해결했다.

**③ 말로 설명하기 (30초)**
> "API 키는 제 계정 요금과 연결되어 있어서 코드에 직접 쓰면 GitHub에 올라가 유출될 수
> 있습니다. 그래서 키는 `.env.local`에 두고 `.gitignore`로 커밋을 막았고, 코드는
> `os.environ.get`으로 이름만 참조합니다. 배포 환경에서는 Vercel 환경 변수에 등록했고,
> 브라우저 코드는 키를 전혀 모르고 서버만 사용합니다. 실제로 디버깅 중 키가 화면에 노출된 적이
> 있어서 바로 폐기하고 재발급했습니다."

**④ 예상 질문**
- *`.env.local.example`은 올려도 되나요?* → 네. 진짜 키가 없는 견본이라서. 대신 진짜
  `.env.local`은 `.gitignore`로 막는다.
- *키가 GitHub에 올라갔다면?* → 파일에서 지우는 것만으론 부족(기록에 남음). **키를 즉시 폐기하고
  재발급**해야 한다.

## 5. 로컬 환경 vs 배포 환경, 그리고 "수정 → 재배포" 흐름

**① 한 줄 답**
로컬은 **내 컴퓨터의 환경**(내가 설치한 Python, `.env.local`), 배포는 **Vercel이 새로 만드는
환경**(의존성 목록으로 새로 설치, 대시보드의 환경 변수)이다. 그래서 로컬에서 되던 게 배포에서
안 될 수 있고, 그럴 때는 **로그로 원인 확인 → 코드 수정 → 재배포 → 재확인**을 한다.

**② 내 프로젝트에서는 — 두 환경의 차이**

| 항목 | 로컬 | 배포 (Vercel) |
|---|---|---|
| 실행 | `flask --app api.app run` 등 내 컴퓨터에서 | Vercel이 요청마다 Function 실행 |
| Python 패키지 | `.venv`에 `requirements.txt`로 설치 | **`pyproject.toml`의 `dependencies`로 새로 설치** (`requirements.txt`는 무시됨) |
| API 키 | `.env.local` (python-dotenv가 읽음) | Vercel 환경 변수 |
| 주소 | `http://localhost:3000` | `https://book-olive-iota.vercel.app` |
| 오류 확인 | 터미널 출력 | `vercel logs` / 대시보드 로그 |

**수정·재배포 흐름 (내가 실제로 한 방식)**
```
증상 발견 → 로그로 원인 확인 → 코드/설정 수정 → 로컬 확인 → vercel --prod 재배포 → 배포 주소에서 재확인
```

**②-2 겪은 문제 기록 (그대로 면접/발표 답변 재료)**

| # | 증상 | 원인 | 어떻게 찾았나 | 수정 |
|---|---|---|---|---|
| 1 | `vercel dev`: "No python entrypoint found" | 최신 Vercel 런타임이 `api/`의 파일 여러 개를 자동 인식 못함 | 오류 메시지 | Flask 앱 1개 + `pyproject.toml` entrypoint 지정 |
| 2 | 로컬에서 `.env.local` 키를 못 읽음 | `vercel dev`가 환경 파일을 Flask에 주입 안 함 | 키가 `None`인 것을 확인 | `python-dotenv`의 `load_dotenv(".env.local")` 추가 |
| 3 | AI 호출이 429 `insufficient_quota` | OpenAI 계정 **크레딧 없음**(무료 프로젝트인데 API는 유료) | 오류 본문의 `credit_balance_exhausted` | AI를 **Gemini 무료 등급으로 교체** (호출부 몇 줄 + 환경변수 이름) |
| 4 | 키를 넣었는데 "키 없음" | 변수 이름이 소문자 `gemini_API_KEY` | 환경 파일의 이름만 확인(값은 가림) | `GEMINI_API_KEY`로 수정 |
| 5 | Gemini 404 "no longer available to new users" | 기본 모델 `gemini-2.5-flash`가 신규 사용자에게 종료됨 | 오류 메시지가 대체 모델을 안내 | 다른 모델로 변경 |
| 6 | `vercel dev`가 `cannot import name 'UTC'`로 죽음 | venv가 아닌 macOS 기본 Python 3.9 사용 (런타임은 3.11+ 필요) | 로그의 `datetime.UTC` 오류 + Python 버전 확인 | venv 활성화 후 실행 |
| 7 | 로컬 페이지 전부 404 (API만 됨) | Flask가 모든 요청을 받는데 HTML/CSS/JS 라우트가 없음 | 로그의 `GET / 404`가 Flask에서 나옴 | 허용 목록(페이지 4개 + css/js/images)만 여는 라우트 추가 (`.env.local` 노출 방지) |
| 8 | 브라우저로 `vercel dev` 접속 시 500 | `vercel dev` 도구가 **동시 요청 2개**에서 Python 프로세스를 죽임 (Python만 직접 실행하면 정상) | 프로세스 감시 + 소켓으로 동시 연결 재현 + 단독 실행과 비교 | 로컬 확인은 Flask 직접 실행으로 우회. 배포엔 무관 |
| 9 | **배포 직후 전부 500** `No module named 'dotenv'` | Vercel은 `requirements.txt`가 아닌 `pyproject.toml`로 설치하는데 목록이 비어 있었음 | `vercel logs`로 런타임 로그 확인 | `pyproject.toml`에 `dependencies` 추가 후 재배포 |
| 10 | 배포 후 간헐적 502 | Gemini 무료 모델 **하루 20회 한도**(429) + 일시적 과부하(503) | 코드가 오류를 삼켜서 안 보임 → 로컬에서 같은 호출 반복해 오류 본문 출력 | 한도 넉넉한 `flash-lite` 모델로 변경, 오류 로그 남기기, 한도 초과 안내 메시지 추가 |

**③ 말로 설명하기 (1분)**
> "로컬에서는 잘 되던 게 배포하니 전부 500이 났습니다. Vercel 로그를 보니 `dotenv` 모듈이 없다는
> 오류였고, Vercel은 requirements.txt가 아니라 pyproject.toml의 dependencies로 패키지를 설치한다는
> 걸 알게 됐습니다. 거기에 패키지 목록을 추가하고 다시 배포해서 해결했습니다. 이처럼 로컬은 제
> 컴퓨터에 이미 설치된 것과 `.env.local`에 의존하지만, 배포는 깨끗한 환경에서 설정 파일 기준으로
> 새로 만들어지기 때문에 차이가 생깁니다. 그래서 배포 후에는 배포 주소에서 다시 전 기능을
> 테스트했습니다."

**④ 예상 질문**
- *로컬과 배포 결과가 다르면 제일 먼저 뭘 보나요?* → ① 배포 로그 ② 환경 변수가 등록됐는지
  ③ 패키지 목록이 설정 파일에 있는지.
- *환경 변수를 Vercel에 등록하고 나면 바로 적용되나요?* → 아니오. **재배포해야** 새 값이 적용된다.

## 6. AI 코딩 도구가 만든 코드라도 "오류 원인을 파악하고 말로 설명"하기

**① 한 줄 답**
AI가 코드를 써 줘도, 오류가 나면 **증상 → 근거(로그·재현) → 원인 → 수정 방향** 순서로
스스로 설명할 수 있어야 한다. 이 프로젝트에서 AI의 첫 시도도 여러 번 틀렸고, 그걸 로그로
확인해서 바로잡았다.

**② 내 프로젝트에서는 — 설명하는 4단계 틀**

> **증상**(무엇이 안 되나) → **근거**(어떤 로그/재현으로 확인했나) → **원인**(왜) → **수정**(무엇을 바꿨고 어떻게 검증했나)

**예시 A — 배포 500 (위 5번 표의 #9)**
- 증상: 배포한 사이트가 모든 요청에서 500(`FUNCTION_INVOCATION_FAILED`)
- 근거: `vercel logs`에서 `ModuleNotFoundError: No module named 'dotenv'`
- 원인: 배포 환경은 `pyproject.toml`의 `dependencies`로 설치하는데 비어 있었음
- 수정: `dependencies`에 flask / openai / python-dotenv 추가 → 재배포 → 배포 주소에서 13개 항목 테스트 통과

**예시 B — "AI 응답이 가끔 실패" (#10)**
- 증상: 같은 요청이 3번 중 2번 502
- 근거: 코드가 `except Exception`으로 오류를 **삼켜서** 원인이 안 보임 → 로컬에서 같은 호출을
  반복하며 오류 **본문 전체**를 출력 → `GenerateRequestsPerDayPerProjectPerModel-FreeTier`, limit 20
- 원인: 무료 모델의 일일 한도(테스트로 소진) + 일시적 과부하
- 수정: 한도가 큰 모델로 변경(25회 연속 성공으로 확인), 오류 로그 추가, 사용자용 안내 메시지

**예시 C — AI가 틀린 부분도 있었다 (솔직하게 말할 수 있어야 함)**
- AI가 기본 모델을 종료된 모델로 지정해 404가 났고, 오류 메시지를 보고 교체했다.
- AI 도구가 키 파일을 통째로 출력해 키가 노출되는 사고가 있었다 → 폐기·재발급, 이후 규칙 수립.
- `vercel dev`가 죽는 문제는 "코드 문제"라고 단정하지 않고, Python만 단독 실행해 보는 **대조 실험**으로
  도구 문제임을 확인했다. → **추측하지 않고 재현·비교로 원인을 좁히는 것**이 핵심.

**③ 말로 설명하기 (1분)**
> "AI 도구가 코드를 만들어 줬지만 실행하면 오류가 났고, 그때마다 로그를 보고 원인을 좁혔습니다.
> 예를 들어 배포 후 전부 500이 났을 때 Vercel 로그에서 `dotenv` 모듈이 없다는 걸 확인했고,
> 배포 환경이 pyproject.toml로 패키지를 설치한다는 걸 몰라서 생긴 문제라 의존성 목록을 추가해
> 재배포했습니다. AI가 종료된 모델명을 쓴 것도 오류 메시지를 보고 고쳤습니다. 저는 AI가 준
> 코드를 그대로 믿기보다, 증상·로그·원인·수정 순서로 확인하면서 사용했습니다."

**④ 예상 질문**
- *AI가 다 짜 준 거 아닌가요?* → 코드 작성은 도움받았지만, 오류가 났을 때 로그로 원인을
  판단하고 방향을 정하는 건 내가 설명할 수 있다. (위 표의 10가지 사례로 답)
- *AI 도구를 쓰면서 조심한 점은?* → 비밀 키를 대화/출력에 노출하지 않기, AI 답을 그대로
  믿지 않고 실행·로그로 검증하기.

- [ ] 프론트에서 AI를 직접 부르면 안 되는 이유를 말할 수 있다

- [ ] 로컬과 배포의 차이 3가지(패키지 설치, 키 위치, 오류 확인 방법)를 말할 수 있다
- [ ] "배포 직후 500" 사례를 증상 → 로그 → 원인 → 수정 순서로 말할 수 있다

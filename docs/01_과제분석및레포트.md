# AI 웹서비스 제작·배포 미션 — 과제 분석 레포트

작성일: 2026-09-18

## 1. 미션 한 줄 요약

AI 코딩 도구를 활용해 **바닐라 HTML/CSS/JS 프론트엔드**와 **Vercel Serverless
Functions(Python) 백엔드**로 구성된 웹 서비스를 만들고, **AI API 기능을 1개
이상 연동**한 뒤 Vercel에 배포하여 실제 URL로 공개한다.

## 2. 제출 패키지 체크리스트 (필수 5종)

### ① 배포된 웹 서비스 (Vercel URL)
- [ ] 페이지/섹션 3개 이상 + 메뉴로 이동 가능
- [ ] 반응형 (모바일에서 레이아웃 정상)
- [ ] AI API 연동 기능 1개 이상 (입력 → 결과 출력)

### ② GitHub 저장소
- [ ] 코드 업로드 및 커밋 이력
- [ ] 프론트(HTML/CSS/JS)와 백엔드(`api/`) 구조 분리

### ③ README.md
- [ ] 서비스 소개, 기술 스택
- [ ] 실행/배포 방법
- [ ] 배포 URL
- [ ] 환경 변수(키) 설정 방법

### ④ 서비스 기획서
- [ ] 서비스 목적, 타겟 사용자
- [ ] 페이지 구성, 핵심 기능
- [ ] AI 기능의 입력/출력/실패 처리 기준

### ⑤ 증빙 자료
- [ ] 스크린샷 세트 (데스크톱 + 모바일 + AI 기능 동작 장면)
- [ ] AI 코딩 도구 사용 과정(대화 로그/스크린샷)

## 3. 기능 요구사항 분해 (진행 순서 7단계)

| 단계 | 내용 | 핵심 산출물 |
|---|---|---|
| 1. 서비스 기획 | 아이디어, 목적, 타겟, 페이지 3개+ 설계, AI기능 정의 | 서비스 기획서 |
| 2. 프로젝트 초기화 | 폴더 구조 구성, GitHub 저장소 생성 | 리포지토리 뼈대 |
| 3. 프론트엔드 구현 | index.html + 추가 페이지/섹션, 네비게이션, 레이아웃 | HTML/CSS/JS |
| 4. 반응형 적용 | 최소 2개 화면 크기(모바일/데스크톱)에서 확인 | 미디어쿼리 |
| 5. AI 기능 UX | 입력 UI, 결과 표시, 실패 처리 1개 이상(빈입력/API오류/지연) | 폼 + 에러 메시지 |
| 6. AI API 연동 | `api/`에 Python 함수, `requirements.txt`, `fetch` 호출 | 서버리스 함수 |
| 7. 배포 및 검증 | Vercel-GitHub 연동, 전체 기능 확인, 문제 시 재배포 | 배포 URL |

## 4. 제약 사항 (반드시 지킬 것)

- **프레임워크 금지**: React/Vue 등 사용 불가 — 순수 HTML/CSS/JS만
- **백엔드는 Vercel Serverless Functions(Python)만** 사용
- **API 키는 반드시 환경 변수로 관리** — 코드/README/스크린샷에 노출 금지
- 키 유출 의심 시 즉시 폐기·재발급하고 노출된 커밋 이력도 정리
- 템플릿/예시를 그대로 복제 금지 (아이디어·문구·구성 변경 필수)
- 배포 URL에서 실제 동작이 재현 가능해야 함 (동료가 접속/테스트 가능)

## 5. 보너스 과제 (선택)

- **운영 자동화/저장 고도화**: 문의·폼 입력 또는 AI 결과를 노코드 자동화 도구나
  간단한 저장소에 연동 ("입력 → 처리 → 저장/알림" 흐름 확장)
- **UX/측정 고도화**: 다크 모드, 마이크로 인터랙션, 방문자 분석 중 1개 이상 적용

## 6. 추천 진행 로드맵 (초보자 기준 예상 시간)

| 순서 | 할 일 | 예상 소요 |
|---|---|---|
| 1 | 서비스 아이디어 확정 + 서비스 기획서 초안 | 0.5~1일 |
| 2 | 프로젝트 폴더 구조 생성 + GitHub 저장소 연결 | 0.5시간 |
| 3 | 메인 페이지 + 2개 이상 섹션/페이지 뼈대(HTML) | 0.5~1일 |
| 4 | CSS 스타일링 + 반응형 적용 | 0.5~1일 |
| 5 | AI 기능 UI(입력 폼, 결과 영역, 에러 메시지) | 0.5일 |
| 6 | `api/` Python 함수 작성 + AI API 연동 테스트(로컬) | 1일 |
| 7 | Vercel 배포 + 환경 변수 설정 + 배포 후 검증 | 0.5일 |
| 8 | README/기획서/스크린샷 등 문서화 | 0.5일 |

> 전체 5~7일 정도를 잡으면 여유 있게 진행 가능. 하루에 몰아서 하기보다
> 단계별로 나눠서 진행하는 것을 권장.

## 7. 평가 관점에서 자주 놓치는 부분 (주의)

- 실패 처리 UX(빈 입력/오류/지연 안내)를 깜빡하고 정상 케이스만 구현
- `.env` 파일을 실수로 커밋 → 반드시 `.gitignore`에 추가
- 데스크톱에서만 확인하고 모바일 테스트를 생략
- 서비스 기획서에 AI 기능의 "실패 처리 기준"을 빠뜨림
- README에 배포 URL이나 환경 변수 설정법을 안 적음
- AI 코딩 도구 사용 증빙(대화 로그/스크린샷)을 마지막에 챙기려다 누락

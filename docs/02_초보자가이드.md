# 웹 개발 초보자를 위한 필수 개념 가이드

이 문서는 이번 미션(바닐라 웹 + Vercel Serverless + AI API)을 진행하는 데
필요한 핵심 개념을 초보자 눈높이로 정리한 것이다. 막힐 때마다 다시 찾아보는
용도로 사용한다.

## 1. HTML / CSS / JavaScript의 역할

| 언어 | 역할 | 한 줄 비유 |
|---|---|---|
| HTML | 구조(뼈대) — 어떤 요소가 있는지 | 건물의 골격 |
| CSS | 스타일(외형) — 어떻게 보이는지 | 건물의 인테리어/외관 |
| JavaScript | 동작(행동) — 사용자와 상호작용, 데이터 처리 | 건물의 전기·자동문 시스템 |

## 2. 사용자 입력 → 요청 → 응답 흐름 (이번 미션의 핵심)

```
사용자가 입력창에 텍스트 입력
  → 버튼 클릭
  → JS 이벤트 리스너 발동
  → fetch()로 /api/xxx 에 요청 전송
  → 서버(Python, api/ 안의 함수)가 AI API 호출
  → 결과를 JSON으로 응답
  → JS가 response.json()으로 파싱
  → DOM에 결과 삽입 → 화면에 표시
```

프론트엔드 예시 코드:

```js
async function getRecommendation() {
  const input = document.getElementById('petInfo').value;

  // 1) 빈 입력 체크 (실패 처리 ①)
  if (!input.trim()) {
    showMessage('필수값을 입력하세요');
    return;
  }

  // 2) 타임아웃 설정 (실패 처리 ②)
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), 10000);

  try {
    const res = await fetch('/api/recommend', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ query: input }),
      signal: controller.signal,
    });
    clearTimeout(timeoutId);

    // 3) API 오류 체크 (실패 처리 ③)
    if (!res.ok) throw new Error('서버 오류');

    const data = await res.json();
    document.getElementById('result').textContent = data.result;
  } catch (err) {
    if (err.name === 'AbortError') {
      showMessage('응답이 지연되고 있어요. 잠시 후 다시 시도해주세요.');
    } else {
      showMessage('오류가 발생했어요. 잠시 후 다시 시도해주세요.');
    }
  }
}
```

## 3. Vercel Serverless Functions란?

- `api/` 폴더 안의 파일 하나가 = 엔드포인트 하나가 된다.
- 예: `api/recommend.py` 파일 → 배포 후 `/api/recommend` 경로로 호출 가능.
- 요청이 올 때만 실행되는 "서버리스(serverless)" 함수라서, 상시 켜져 있는
  서버를 직접 관리할 필요가 없다.

Python 함수 기본 구조 예시:

```python
# api/recommend.py
from http.server import BaseHTTPRequestHandler
import json
import os

class handler(BaseHTTPRequestHandler):
    def do_POST(self):
        content_length = int(self.headers.get('Content-Length', 0))
        body = json.loads(self.rfile.read(content_length) or b'{}')
        query = body.get('query', '').strip()

        if not query:
            self._send_json(400, {'error': '필수값을 입력하세요'})
            return

        api_key = os.environ.get('AI_API_KEY')
        if not api_key:
            self._send_json(500, {'error': '서버 설정 오류입니다'})
            return

        try:
            # 여기서 실제 AI API(OpenAI, Claude 등) 호출
            result = call_ai_api(api_key, query)
            self._send_json(200, {'result': result})
        except Exception:
            self._send_json(502, {'error': 'AI 서비스 호출에 실패했어요'})

    def _send_json(self, status, data):
        self.send_response(status)
        self.send_header('Content-Type', 'application/json')
        self.end_headers()
        self.wfile.write(json.dumps(data).encode('utf-8'))
```

> Vercel Python 런타임은 `BaseHTTPRequestHandler` 방식 또는 최신 문서 기준
> 다른 시그니처를 요구할 수 있으니, 실제 구현 시 Vercel 공식 문서의 최신
> Python 런타임 가이드를 확인한다.

## 4. 환경 변수(API 키)를 코드에 직접 쓰면 안 되는 이유

- GitHub에 코드를 올리는 순간 API 키가 전 세계에 공개된다.
- 누군가 그 키를 가져가 악용하면 과금 폭탄을 맞을 수 있다.
- 그래서 키는 코드에 적지 않고 **환경 변수**로 분리해서 관리한다.

설정 방법:
1. 로컬에서는 `.env.local` 파일에 `AI_API_KEY=sk-xxxx` 형태로 저장
2. `.env.local`은 반드시 `.gitignore`에 추가해서 커밋되지 않게 한다
3. Vercel 배포 환경에서는: **Vercel 대시보드 → 프로젝트 → Settings →
   Environment Variables**에서 같은 키/값을 등록
4. 코드에서는 `os.environ.get('AI_API_KEY')`로 읽어온다

## 5. 로컬 환경 vs 배포 환경의 차이

| 구분 | 로컬(Local) | 배포(Production) |
|---|---|---|
| 실행 방법 | `vercel dev` 로 로컬 서버 실행 | `git push` → Vercel이 자동 빌드/배포 |
| 환경 변수 | `.env.local` 파일 | Vercel 대시보드에 등록 |
| 확인 방법 | `http://localhost:3000` | 실제 배포 URL |

배포 후 문제가 생기면:
1. Vercel 대시보드 → 해당 프로젝트 → **Functions/Logs**에서 에러 로그 확인
2. 원인 파악 후 코드 수정
3. 다시 `git push` → Vercel이 자동으로 재배포

## 6. Git / GitHub 기본 흐름

```bash
git init                     # 저장소 초기화 (최초 1회)
git add <파일명>              # 변경사항 스테이징
git commit -m "메시지"        # 커밋
git remote add origin <URL>  # 원격 저장소 연결 (최초 1회)

```


## 7. 반응형 디자인 기초

- 뷰포트 메타 태그는 모든 HTML `<head>`에 필수:
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  ```
- 미디어 쿼리로 화면 크기별 스타일 분기:
  ```css
  /* 기본: 데스크톱 */
  .nav { display: flex; flex-direction: row; }

  /* 768px 이하 (태블릿/모바일) */
  @media (max-width: 768px) {
    .nav { flex-direction: column; }
  }
  ```
- 크롬 개발자도구(F12) → 기기 툴바(Toggle device toolbar)로 모바일 화면 확인 가능

## 8. AI API 실패 처리 UX 패턴 (미션 필수 요구사항)

과제 요구사항상 아래 3가지 중 **최소 1개**는 반드시 구현해야 한다.

| 상황 | 처리 방법 | 사용자에게 보여줄 메시지 예시 |
|---|---|---|
| 빈 입력 | 요청 보내기 전 JS에서 먼저 체크 | "필수값을 입력하세요" |
| API 오류(4xx/5xx) | `fetch`의 `res.ok` 체크 + try/catch | "오류가 발생했어요. 잠시 후 다시 시도해주세요" |
| 지연/타임아웃 | `AbortController`로 일정 시간 후 요청 취소 | "응답이 지연되고 있어요. 잠시 후 다시 시도해주세요" |

## 9. AI가 짜준 코드를 이해하고 디버깅하는 법

1. 에러 메시지를 정확히 읽는다 — 어떤 파일, 몇 번째 줄에서 에러가 났는지
2. 브라우저 개발자도구(F12) → **Console** 탭: JS 에러 확인
3. 개발자도구 → **Network** 탭: fetch 요청/응답 실제 내용 확인 (요청이
   제대로 갔는지, 응답 상태 코드가 몇 번인지)
4. Vercel 대시보드의 배포 로그: 서버(Python) 쪽 에러 확인
5. 모르는 코드가 있으면 AI 코딩 도구에게 "이 코드가 정확히 뭘 하는지
   한 줄씩 설명해줘"라고 요청해서 이해하고 넘어간다 (베껴쓰기 금지 —
   원리를 알아야 나중에 직접 수정 가능)

## 10. 자주 하는 실수 모음

- `api/` 폴더 안 파일명과 실제 호출하는 URL 경로가 다름 (오타 주의)
- `requirements.txt`를 안 만들어서 배포 시 패키지 설치 실패
- 환경 변수 이름을 코드와 Vercel 대시보드에서 다르게 씀 (대소문자까지 정확히 일치해야 함)
- 로컬에서는 됐는데 배포 후 안 되는 경우 → 대부분 환경 변수 미설정 문제
- 모바일 테스트를 개발 끝나고 한 번에 몰아서 하다가 레이아웃 깨짐을 늦게 발견
